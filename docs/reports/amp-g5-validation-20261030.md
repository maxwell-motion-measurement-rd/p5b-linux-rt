# G5（检查长测与重复启动） 长时间负载与重复启动验证记录

日期：2026-10-30，P5（XCZU4EV）。结论：**本轮 G5 通过**。G0—G5（检查长测与重复启动） 的最小通信实验验证完成；结论限于 r001（本实验第1次修订的基础启动版本） 基础镜像与 r004（本实验第4次修订的通信驱动与裸机程序版本） RAM 载荷，不包含电机闭环及产品硬实时验收。

沿用 r001 SD 基础镜像及 r004 RAM 固件／驱动；Linux 在线核为 0—2，Core3 独立运行。保留 G4（检查故障识别与恢复） 故障注入形成的累计非零计数，G5 正常长测以计数增量判断新增错误，不清零既有证据。

## 验证配置

三种条件分别执行正向、反向、交叉通信各 60000 次；各模式目标 100Hz，按绝对单调时钟节奏发送，超期后跳过已错过的发送时隙并记录 missed_release。每种条件至少 30 分钟，总计 540000 个测试事务；握手和反向完成消息另计帧数。

载荷轮换 0、1、4、63、64、65、255、256 字节及六种数据模式。保留每笔事务延迟，统计吞吐与延迟分布，检查 CRC（Cyclic Redundancy Check，循环冗余校验，用校验值发现消息数据损坏）、字节、序号、会话、epoch（通信服务状态的版本标识，服务重置时更新） 和关联序号。本阶段不承诺产品截止时间。

- 空载：无额外负载进程，保留系统与监测开销。
- CPU：三个 SCHED_OTHER 整数运算进程，分别绑定 Linux CPU0、1、2。
- 内存：三个 SCHED_OTHER 进程分别绑定 CPU0、1、2，每进程两个 128MiB 缓冲区，共 768MiB；循环填充、复制并比较。此条件同时产生 CPU 与内存带宽负载。

负载进程每个最多运行 3600 秒；正常结束或测试失败时，阶段脚本只终止自己启动的负载进程并收集退出状态。每 10 秒保存 CPU 时间、可用内存、Core3 状态和通信计数；Linux 监测程序约每 45 秒经串口检查进度。阶段前后保存完整内核日志和驱动快照；首个通信失败即退出该阶段，不自动重测。

正常长测之外，在本 G5 内另做 10 次 Linux 测试程序重启、10 次裸机通信服务重置（不是硬件 Core3 复位），每次恢复后验证 100 次合法回显。再做 5 次由用户配合的完整冷启动；每次重新上传并核对 r004，查询 Core3 关断状态后单次启动并验证通信。不会把先前 G4 的成功次数直接算入本轮 G5。

## 完成状态与边界

板子保持 Linux CPU0—2 与 Core3 r004 运行，通信测试程序已退出，故障注入关闭；模块不热卸载。SD 仍为 r001 基础镜像，r004 固件／驱动仅在 RAM，重启后不会自动恢复本轮通信载荷，需要重新上传、核对并单次启动。五次冷启动验证的是这条人工重载实验流程，未验证持久化开机自启动。
